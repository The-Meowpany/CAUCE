# CAUCE i18n Policy

## Rule

Code identifiers, comments and machine values are **English only** —
that's what keeps diffs, logs and schemas greppable across the whole
team. Every string a human reads goes through a presentation
dictionary with an English fallback. Domain values stay neutral codes
(`VALID`, never "Válido"; `heat_event`, never translated).

## Coverage

| Surface | Mechanism | Languages | Default |
|---|---|---|---|
| Node dashboard SPA | `I18N` dict in `WebAssets.cpp`, `data-i18n` keys, browser-language pick saved in `localStorage` | es, en | es |
| Central dashboard `/` | `_LABELS` in `dashboard.py`, `Accept-Language` negotiation, `?lang=` override, segmented switcher in the top nav (server-rendered, no JS) | en, es, pt | es |
| API / sync / CSV | Snake-case machine codes only (`invalid_signature`, `rate_limited`); CSV headers are interchange schema, always English | — | — |
| `scripts/*.ps1` | `$T` message tables, `CAUCE_LANG=en` switches to English | es, en | es |
| `simulator/` | `_STRINGS` table, `CAUCE_LANG=es` switches to Spanish | en, es | en |
| Logs (serial, server) | Structured event codes (`SYNC_BATCH_ACKED`), never prose | — | — |

## Adding a language

1. Add the locale table next to the existing ones — same keys, same
   order, no freelancing.
2. Keep machine tokens byte-identical (`E2E_OK`, `E2E_DB`, CSV
   headers, error `detail` codes). Log parsers and tests depend on
   them; one translated token breaks the E2E suite.
3. Wire negotiation where the surface supports it
   (`Accept-Language`, browser language, `CAUCE_LANG`); otherwise fall
   back to the default and move on.
4. Docs: mirror the policy here (`docs/en/I18N.md` +
   `docs/es/I18N.md`); user docs live mirrored in `docs/en/` +
   `docs/es/`.

## What NOT to translate

Commands, paths, config keys, log codes, CSV/JSON schemas, protocol
constants, identifiers. Translating any of these breaks machines, and
"machines" includes the person grepping logs at 2 AM.
